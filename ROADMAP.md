## Invocation reliability — make sure mnemos is called at the right time

Claude Code exposes ~26 hook events; we ship 7, spanning passive (SessionStart, UserPromptSubmit, PostToolUse, SessionEnd, PreCompact, PostCompact) and blocking (PreToolUse guardrail). A memory system nobody invokes is zero value regardless of schema quality, so this layer gates everything downstream.

**Shipped**

- [x] `SessionStart` → `mnemos prewarm` (passive context injection)
- [x] `UserPromptSubmit` → `mnemos hook user-prompt` (backfills session goal from the first prompt — kills the "agent skipped mnemos_session_start on editing tasks" failure mode)
- [x] `PostToolUse` (`Edit|Write|MultiEdit|NotebookEdit`) → `mnemos hook post-tool` (passive file-touch capture; the heat map no longer depends on the agent remembering to call `mnemos_touch`)
- [x] `SessionEnd` → `mnemos hook session-end` (auto-closes with derived summary; reason-mapped status: `prompt_input_exit` → `StatusAbandoned`, `bypass_permissions_disabled` → `StatusBlocked`, everything else → `StatusOK`)
- [x] `PreCompact` / `PostCompact` → `mnemos hook pre-compact` / `post-compact` (emits a recovery block to stderr — `PreCompact`'s stderr is fed back to Claude so mnemos state survives compaction instead of being silently dropped for one turn)
- [x] **First blocking-hook** — `PreToolUse` matched on `mcp__mnemos__mnemos_save|mnemos_correct|mnemos_convention` runs the safety scanner; exit 2 with stderr feedback when a RiskHigh prompt-injection pattern is detected. Opens the exit-2-stderr guardrail pattern.

**Next blockers — extend the exit-2-stderr guardrail pattern**

The safety-scanner guardrail on `mnemos_save` / `_correct` / `_convention` proved the pattern. Remaining hooks that would turn memory from "hint the agent may ignore" into active enforcement:

- [ ] **`PreToolUse` on `Bash` for `git commit`** — block commits whose message carries AI attribution phrasing when the project has a stored correction against it. The attribution-free-commits correction is already in user memory; this hook makes the rule actually land instead of relying on the agent to remember.
- [x] **`PreToolUse` on `Edit` / `Write` — just-in-time memory.** Shipped as the advisory half: the hook searches corrections/conventions by the target file's path tokens and returns matches as PreToolUse `additionalContext`, so the memory arrives at the decision point instead of 40 turns earlier in prewarm. Never emits a `permissionDecision` (must not bypass or block the permission system), dedupes against the injection log per session (repeat edits to the same file stay silent), and logs surfacings under the `pre_tool` channel. The *blocking* half — deterministic checkers that exit-2 on contradicted patterns — is Bet 5 and still open.
- [ ] **`TaskCreated` / `TaskCompleted`** — gate on rumination queue for the topic; surface high-severity candidates before the agent commits to an approach.
- [ ] **`SubagentStart` / `SubagentStop`** — cascade subagent learnings back to the parent session so corrections made inside a subagent don't get lost.

**Distribution — same mechanism, different hosts**

- [ ] **Multi-agent installers** — `mnemos init` only knows Claude Code today. Each other host has the same "harness hook" concept under a different name: Cursor has `.cursor/rules` + hooks in preview, Windsurf has Cascade rules, Codex CLI has AGENTS.md, Gemini CLI has its own. Mechanism is the same (hook, not agent judgement); config files differ. Ride on Bet 3's spec once that lands; until then, ship host-specific installers for the ones people actually use.
- [ ] **Skill pack registry** — moved down from "Next up" (lower priority than invocation reliability; Anthropic's Agent Skills ecosystem already claimed this category).

## The three bets — April 2026 frontier plays

Two deep-research passes (competitive landscape + academic frontier + user pain) converged on the same three moves. Ranked by leverage. See `docs/research/2026-04-frontier.md` for the full evidence trail.

- [ ] **Bet 1 — Symbol-anchored memory (*the launch headline*)** — memories keyed to AST/LSP symbol identity (SCIP string when an indexer exists; tree-sitter AST hash of the symbol body as content-address; git `-L`-style follow as fallback). On rename/move the memory re-anchors; on deletion it orphans with full provenance. Sibling-symbol retrieval ("this memory applies to `TransferService.Reconcile` — also surface for matching interfaces"). **Claim nobody else can make:** *mnemos memories survive refactors.* Every shipping memory product (mem0, Zep, Letta, MemPalace, agentmemory, CLAUDE.md, Cursor rules, Windsurf memories) is prose-keyed or path-keyed and rots on refactor. Serena MCP is the closest living relative and even it stops at "LSP for reading code" — its memories are free text. Solves the top-ranked user pain: *memory rot* (mem0 issue #4573 documented a 97.8% junk rate where a single hallucinated "User prefers Vim" fact re-ingested into 808 entries). Demo is one `gopls rename` away.

- **Bet 2 — Provenance graph + quarantined tool-output tier (*the depth story*)** — every memory carries `source_kind` (user | tool | agent_inference | dream | import), a `derived_from[]` DAG of parent memories, and a `trust_tier` (raw | curated | skill). Tool-output and browsed-content memories start in `raw` and can only be promoted via user confirmation, rumination, or the dream pass before they're surfaced as facts. Every `mnemos_search` response includes its provenance chain. Addresses three pains at once: **memory poisoning** (MemoryGraft / MINJA / "Poison Once, Exploit Forever" — persistent compromise via poisoned memory is live as of Q1 2026 and almost no shipping product sandboxes tool-derived writes), **the "why" gap** (systems save *what* but never *why* — explicitly called out as unexplored in the 2025 memory surveys), and **hallucination feedback loops** (the mem0 97.8% junk came from no grounding check between extraction and storage). Composes naturally with our existing `ContradictionDetectedMonitor` — it can now surface which chain to trust.
    - [x] **Phase 1 — substrate.** Migration 0003 adds `source_kind` / `trust_tier` / `derived_from` columns with CHECK constraints and defaults (existing rows become `user` / `curated` / `[]`). `memory.SourceKind` and `memory.TrustTier` enums, struct fields on `Observation` and `SaveInput`, service defaults + validation, storage round-trip, full test coverage.
    - [x] **Phase 2 — MCP surface + search quarantine.** `mnemos_save` accepts optional `source_kind` / `trust_tier` / `derived_from`; its response echoes them. New `mnemos_promote(id, to_tier, why_better)` tool moves observations between tiers with a Popper-style 16-char-minimum justification guard (same threshold as ruminate_resolve). `mnemos_search` excludes raw-tier rows by default — `include_raw=true` to surface quarantined content — and every hit now carries `source_kind` / `trust_tier` / `derived_from` so callers can see provenance without a second round trip.
    - [x] **Phase 3 — rumination integrates provenance.** New `StaleRawObservationMonitor` flags raw-tier observations older than `stale_raw_days` (default 14) — sits in the rumination queue so the agent chooses between `mnemos_promote` and dismiss. `ContradictionDetectedMonitor` now weighs raw-tier contradictors at half a curated vote (floored at 1), so a target contradicted only by raw evidence surfaces at low severity instead of medium/high. The reason string names the curated/raw split so the reviewer sees exactly which sources drove the flag. `LinkEdge` carries `SourceTrustTier` and `TargetTrustTier` so consumers get provenance without a round-trip.
    - [ ] Phase 4 — export/import carries provenance: vault sync + skill packs preserve `source_kind` / `derived_from` so portable memories keep their chain.

- [ ] **Bet 3 — `mcp-memory-spec` as an open protocol (*the category play*)** — draft a minimal memory schema as an MCP SEP: `memory/save`, `memory/search`, `memory/link`, `memory/invalidate`, `memory/provenance`, `memory/promote`. Bi-temporal (`t_valid`, `t_invalid`, `t_observed`) and provenance fields are first-class. Publish mnemos as the reference implementation and submit to modelcontextprotocol/modelcontextprotocol. The 2026 MCP roadmap calls out Tasks, Server Cards, streamable HTTP — **nothing memory-specific**. MemPalace, agentmemory, Memorix, OpenMemory MCP all hand-roll incompatible schemas. First mover defines the category. Reframes mnemos from "another memory tool" to **the standard everyone else implements**.

## Newer bets — May 2026 frontier plays

Three more architectural moves from deep-research passes after watching the v0.5.x cycle. These compose with the existing trio rather than competing with it. Bet 4 is post-hoc accountability for what shipped, Bet 5 is forward-looking enforcement so the wrong code can't ship in the first place, Bet 6 turns the whole system into a laboratory where the past is a queryable parameter. Together they reframe mnemos from "memory layer" to "memory substrate for AI coding agents."

- [ ] **Bet 4: Causal memory attribution (*the measurement story*).** Every memory injected into prewarm or context carries a stable opaque token (`<m:01K2...>`) woven into its framing. The post-session trace scanner picks up downstream effects of each token in the transcript: explicit citation, behavioral alignment with the memory's `fix` field, refusals that match `wrong_because`. Regex plus structural matching against the schema, no LLM judge in the loop. The dream pass periodically re-runs sampled past sessions with one memory withheld; the behavior delta becomes that memory's causal score. Skill promotion gates on the cluster's causal contribution crossing a threshold, clustering alone is no longer sufficient. Memories that retrieve daily but never contribute decay. Compounds with the verify harness (per-memory ablation is per-session ablation at finer grain) and Bet 2's provenance chain (causal score becomes a column on every observation). **Claim nobody else can make:** *we know which memories are actually doing the work.* Every other memory product treats memories as fungible context-stuffing. RAG citation, mech-interp ablation studies, paired-arm A/B testing exist separately, but composing them into per-memory causal scoring for an agent memory layer hasn't been done as far as I've found. The compounding payoff is the causal graph across memories: pairs that individually do nothing but together always tip a decision the right way become candidate composite skills humans would never write by hand. Rumination gets sharper too, because when a skill fails to influence outcome the failed transcript becomes concrete evidence in the hostile-review pack.

- [ ] **Bet 5: Executable memory, corrections compile to AST guards (*the enforcement story*).** When a correction repeats enough to promote, mnemos doesn't just write the skill text. It synthesises a small deterministic AST checker bound to the skill, and the checker runs as a `PreToolUse` hook on `Edit` and `Write` to block the wrong code before it lands. Mechanism is template-based pattern extraction over the `tried` field of a correction. Examples: a correction about `time.Now()` in `_test.go` files template-matches a tree-sitter AST query for `time.Now()` calls in files under `*_test.go`; corrections about banned imports template-match an import-presence checker; corrections about missing error wrapping bind to a vet-style `%w` checker. The template library starts narrow (banned imports, banned APIs in specific file globs, missing error wrapping, hardcoded timeouts in `_test.go`) and grows when corrections repeatedly fail to template-match. The growth itself is the interesting research question: how much of natural-language correction prose can be deterministically turned into AST queries. **Claim nobody else can make:** *conventions become AST guards at write time, with provenance back to the originating corrections.* Lint rules and type-checker plugins both require human authorship. Auto-deriving a deterministic checker from a natural-language correction is the novel bridge. Closes the capture-side ceiling end-to-end: even if the agent never reads the prewarm, even if capture rate stays at 53%, the wrong code can't ship because the hook fires at the file boundary instead of the memory boundary. Composes with Bet 1 (symbol-anchored memories give the checker a stable target so refactors don't break the rule) and rides the existing safety-scanner exit-2-stderr pattern (already proven to redirect agent behavior with stderr feedback fed back to Claude). Demos in 30 seconds: type `time.Now()` into a `_test.go` file, watch the write get rejected with a stderr citation pointing back to the originating correction.

- [ ] **Bet 6: Counterfactual replay, the time-machine memory layer (*the laboratory story*).** Record session snapshots that are deterministic enough to replay (tool inputs/outputs, file contents at the time, prompts, decisions, content-addressed and immutable), then re-run any past session with a different memory configuration and measure the behavior delta against the original. The verify harness is the present-tense version of this; counterfactual replay is the same idea parameterized by time. Replays live in the dream pass and cost agent tokens, so the scheduler prioritizes high-value runs: candidate skill promotions, falsifiability tests for ruminated skills, marginal-value-of-X for any memory worth measuring. Same paraphrase-tolerant scanner from Bet 4 handles the transcript comparison. **Claim nobody else can make:** *the past is a queryable parameter, not a read-only record.* Every shipping memory system treats history as fixed; counterfactual replay makes "would this correction have mattered three months ago" an actual query you can answer with evidence. Closest analogs are reproducible builds and log-replay debuggers; none of them parameterize on memory state because none of them have memory states worth parameterizing on. The bi-temporal substrate (`t_valid` / `t_invalid` already define "what was the store at time T") plus snapshot replays close the loop. What it unlocks: empirical skill promotion ("propose from a single correction, replay 10 sessions where it would have applied, promote on counterfactual evidence"), skill obsolescence detection ("withhold the skill in replay, behavior identical → dead weight"), quantitative onboarding evaluation when a new model ships ("replay scenario set against Claude 5 vs Claude 4, score the difference"), refactor impact prediction (replay sessions involving a renamed symbol with the new name in scope), conventions-as-experiments (replay with a candidate convention, see if it would have changed outcomes), and a real test loop for ruminated `why_better` predictions. Subsumes the verify harness as the special case where the parameter is "all memories or none" and Bet 4's per-memory ablation as the special case where you toggle one bit. Compounds with all five prior bets: Bet 1 makes symbol-anchored replay clean across renames, Bet 2's provenance lets you replay with a specific trust tier withheld, Bet 4's scanner is reused for transcript diff, Bet 5's AST guards get a historical-bug-prevention test loop. Risk: agents are stochastic, so a single replay isn't signal; need n=K paired runs with seeded sampling and distributions, same discipline as the verify harness today.

## June 2026 research pass — measurement first

A third deep-research pass (105 agents, adversarial 3-vote verification, 21/25 claims confirmed; evidence trail in `docs/research/2026-06-frontier.md`) after the v0.5.x cycle. Headline: the field moved from "can agents remember" to "can memory be governed and proven useful," and OpenMemory (CaviraOSS) has claimed the local-first SQLite MCP niche, so that posture alone no longer differentiates. Our defensible ground is code-awareness (Bet 1, still unclaimed), governance (Bet 2, shipped), and measured usefulness (Bet 4, now the most externally validated bet we have — MemoryArena shows recall benchmarks don't predict agentic usefulness, and the March 2026 survey names causally grounded retrieval an open problem nobody ships). **Re-prioritization: Bet 4 moves ahead of Bet 1 in build order.** Ship the measurement substrate first so Bet 1 launches with receipts instead of assertions.

- [x] **`mnemos_premortem` (*decision-time memory*).** New MCP tool: the agent submits its plan before executing; mnemos returns how similar attempts failed — matching corrections with full tried/wrong/fix substance, past sessions with overlapping goals that ended failed/blocked/abandoned, applicable skills flagged when under rumination, and conventions the plan must respect. Empty result returns an explicit "no recorded failures match — proceed" verdict. Moves memory from "before the task" (prewarm) to "inside the decision"; surfacings logged under the `premortem` channel so Bet 4 can score whether premortems actually prevent failures.

New candidates from the pass, ranked by leverage × novelty × feasibility:

- [x] **Outcome-gated skill promotion** — first-time promotion now requires, beyond the count ≥ 3 floor: recurrence spread (≥2 sessions or days, not one burst) plus one piece of outcome evidence — the cluster recurred AFTER being surfaced into context (read from the injection log: passive memory demonstrably failed), a correction was born in a failed/blocked session, or the cluster hit 5+ corrections (overwhelming frequency). Version bumps of already-admitted skills skip the gate (maintenance, not admission); embedded callers that don't wire the outcome stores keep legacy frequency-only behavior. Every admit/defer decision logs an explainable reason and deferrals are counted in the dream journal. Inspired by Skill-Pro's PPO Gate (ICML 2026 spotlight: outcome-verified admission yields 0.925 in-domain reuse vs 0.091 for frequency-style baselines), adapted to signals available without action log-probs.
- [ ] **Role-aware subagent memory routing** — upgrades the SubagentStart/Stop item above: LEGOMem (Microsoft, AAMAS 2026) shows orchestrator-level memory placement dominates (+13 points; orchestrator-only beats agent-only), so inject at the planning/delegation layer first, cascade subagent learnings second. Bonus narrative: memory lets smaller/local models beat larger memory-less teams.
- [ ] **Interpretable admission gate** — deterministic five-factor score (future utility, factual confidence, semantic novelty, temporal recency, type prior) upstream of `trust_tier`, logged into provenance, so every memory answers "why was this stored" (A-MAC, ICLR 2026 workshop). Attacks the mem0 97.8%-junk failure at the front door.
- [ ] **Composite adaptive trust scoring** — multi-signal trust score layered over the discrete tiers; static cutoffs fail in both directions (arXiv 2601.05504). Must not break provenance auditability.
- [ ] **Governance scorecard** — self-assess against the nine mnemonic-sovereignty primitives (arXiv 2604.16548: no published architecture covers all nine), publish the scorecard, close the cheap gaps. Positioning artifact and roadmap in one; the window is narrowing.
- [ ] **Agent-synthesized tools as skills** — *parked pending verification*: the claim that Live-SWE-agent doesn't persist evolved tools cross-task was refuted in adversarial review, so verify their persistence story before treating this as differentiation.

## Deprioritized after frontier research

- ~~**Cross-agent federation as a headline feature**~~ — MemPalace (19.5k stars in two weeks) and agentmemory (Cognition) already own the undifferentiated "works across Claude/Cursor/Codex" slot. Don't race there — out-schema them via Bet 3 instead.
- **"Local-first SQLite memory over MCP" as a positioning claim** — OpenMemory (CaviraOSS, 4.2k stars) ships self-hosted SQLite, native MCP for Claude Desktop/Cursor/Windsurf, a temporal knowledge graph with point-in-time queries, multi-sector decay, and composite retrieval scoring (verified June 2026). It lacks bi-temporality, code-awareness, provenance/trust governance, and corrections-to-skills — lead with those, not the posture.
- ~~**Skill pack registry**~~ (moved from "Next up") — Anthropic's Agent Skills + `skill-creator` ecosystem already claimed this category. Our procedural-memory edge is corrections→skills auto-promotion, not a marketplace. Keep the promotion pipeline, skip the registry.
- **Chasing LongMemEval numbers as primary KPI** — Hindsight hits 91.4% with a 20B model. Our edge isn't conversational-recall benchmark-chasing; it's code-aware, provenance-rich, local-first memory those benchmarks don't measure. Better play: define a refactor-survival benchmark and own that one.
